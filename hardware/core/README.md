# KO core board (KiCad project)

- **Contract:** [docs/contracts/core-board.md](../../docs/contracts/core-board.md)
- **Design note (parts, power tree, pin map, schematic decisions):** [docs/design/core-board-rev-a.md](../../docs/design/core-board-rev-a.md)
- **Status:** rev A as a 16 × 80 mm strip beside the keys (D-41, D-43): schematic verified, PCB placed and routed by script (4 layers), JLCPCB files in `fab/`. Only USB-C port A and the battery connector are connectors; switch, NTC, SWD, haptic and underglow wires solder to pads on the bottom.

## The schematic is generated

`tools/gen_schematic.py` is the source of truth: every part, value, footprint, LCSC number and net is defined
there. It writes the KiCad files below. **Do not edit the schematic in KiCad**; your changes would be overwritten.
Edit the Python, then regenerate and check:

```bash
python3 hardware/core/tools/gen_schematic.py
```

```bash
python3 hardware/core/tools/check_schematic.py out/
```

The check fails on any ERC error and on any difference between KiCad's netlist and the intended nets. It also
writes `ko-core-schematic.pdf` and `ko-core-bom.csv` to the output folder.

| File | Content |
|---|---|
| `ko-core.kicad_sch` | Root sheet with the six block sheets |
| `power.kicad_sch` | Battery and charger: BQ25628E, LiPo and NTC connectors, MAX17048 |
| `power_rails.kicad_sch` | Power switch, 3.0 V LDO, 5 V boost, 5 V mux, LED rail switch |
| `mcu_radio.kicad_sch` | BMD-340 (nRF52840), 32.768 kHz crystal, I²C pull-ups |
| `usb.kicad_sch` | USB-C port A, port B inputs, TPS2121 VBUS mux, TS3USB221A data switch, CC resistors, ESD |
| `switchboard_conn.kicad_sch` | 33 castellated contacts to the switch board (pinout fixed by the contract) |
| `service.kicad_sch` | SWD header, test points, haptic connector (DNP), underglow port |
| `lib/ko.kicad_sym`, `sym-lib-table` | Project symbols drawn from datasheets (generated) |
| `bom/parts_query.json`, `bom/parts.csv` | Part queries and resolved LCSC numbers (`hardware/tools/jlc_lookup.py`) |
| `ko-core.kicad_pcb`, `ko-core.kicad_pro` | 4-layer, 1.0 mm, 16 × 80 mm strip, generated by `tools/gen_pcb.py` (placement, net classes, planes, antenna keep-out) |
| `lib/ko.pretty`, `fp-lib-table` | Custom footprints, generated by `tools/gen_footprints.py` from the manufacturers' drawings |
| `route/ko-core-maze.json` | Routed tracks and vias found by the grid maze router (source of truth for them) |
| `fab/` | Rev A manufacturing files, written by `tools/fab_outputs.py` |
| `tools/` | `gen_schematic.py` (design data), `check_schematic.py` (verification), `gen_footprints.py`, `gen_pcb.py` (placement), `route_pcb.py` (hand-routed power and buses, GND fan-out, maze routing, stitching, zone fill); run the PCB scripts with KiCad's Python: `/usr/bin/python3` |

The generator library lives in [`hardware/tools/kisch`](../tools/kisch) and will be reused for the switch board,
the dongle and the modules.

## The PCB is generated too

```bash
/usr/bin/python3 hardware/core/tools/gen_pcb.py
```

```bash
/usr/bin/python3 hardware/core/tools/route_pcb.py
```

`gen_pcb.py` places every part from the schematic netlist. `route_pcb.py` rebuilds the copper: the power paths
drawn in code, a GND via for every SMD GND pad, the stored maze-router tracks
(`route/ko-core-maze.json`), stitching vias and the pours. `route_pcb.py --maze` routes again whatever is open
(about 20 minutes; set `MAZE_CACHE=/some/file.json` to keep the slow negotiation step between runs).
`route_pcb.py --repair` closes connections that are still open by moving only the stored routes in their way.

## Manufacturing files

```bash
/usr/bin/python3 hardware/core/tools/fab_outputs.py
```

Writes `fab/`: Gerbers and drills (zip), JLCPCB BOM and CPL, a 1:1 PDF for the fit check and three renders. It
refuses to run unless DRC is clean. The rev A files are committed; see the design note, §9 "Ordering at JLCPCB",
for what to check before ordering.
